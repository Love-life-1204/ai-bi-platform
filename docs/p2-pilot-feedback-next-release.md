# 客户试点反馈与下一版本规划

状态：待真实试点数据填充。本文不把内部假设写成客户结论。

## 反馈证据模板

每条反馈至少记录：试点客户匿名编号、角色、发生时间、任务场景、原始表述摘要、可复现步骤、影响范围、关联 trace/query/task ID、现行绕行方案、是否涉及安全或数据正确性。任何客户敏感信息仅保留在获批系统，本文只放匿名结论和证据引用。

## 优先级评分

采用可复算分数：

```text
Priority = (业务影响 1—5 × 发生频率 1—5 × 证据置信度 0.5/0.8/1.0)
           + 商业化加分 0—5 + 安全/正确性加分 0 或 10
           - 实施成本 1—5 - 运行风险 1—5
```

安全、租户隔离、指标正确性问题不受总分排序，直接进入阻断队列。预测精度偏好、视觉样式和模型选择不能阻塞 P0/P1 商业能力。

## 版本决策节奏

1. 每周归并重复反馈并补齐证据，不直接承诺排期。
2. 双周由产品、数据、后端、AI、安全共同复核评分和回滚成本。
3. 版本冻结前仅接收安全、正确性和商业阻断级变更。
4. 灰度按租户白名单开启 `ANALYTICS_ENABLED`；先内部、再设计伙伴、最后一般可用。
5. 任一阶段出现跨租户风险、指标口径错误或查询 P95 回退超过 20%，立即关闭开关并回到稳定版。

## 下一轮输出物
