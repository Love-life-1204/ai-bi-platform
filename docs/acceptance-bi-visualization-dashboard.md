# BI 可视化图表和看板阶段验收

## 验收结论

步骤 112—123 已形成可运行闭环：有 `dashboard:manage` 的成员可以从已发布数据集和指标创建、校验、版本化发布图表，将已发布图表编排为 12 列网格看板；有 `dashboard:read` 的成员只能读取正式版本，并且每次加载都通过统一查询服务重新应用该成员的租户上下文、权限版本、行列策略和发布批次。

## 功能对应

| 步骤 | 实现与验收点 |
|---|---|
| 112 | `ChartView` 支持 KPI、柱状图、折线图，ECharts 图表按需注册。 |
| 113 | 支持饼图、堆叠柱状图和可滚动明细表。 |
| 114 | 服务端 `ChartSpecValidator` 校验安全声明式配置；前端 `validateChartBinding` 校验维度、指标和数值类型。任意脚本、HTML、回调和未知根配置均被拒绝。 |
| 115 | `/api/charts` 完成创建、编辑、校验、发布和版本查询；已发布版本不可原地修改，编辑自动建立后继草稿。 |
| 116 | `/api/dashboards` 完成创建和编辑；布局强制为 12 列合法坐标，前端支持拖拽并用乐观锁保存。 |
| 117 | 看板查询接受全局半开时间范围和维度筛选，并与图表固定查询计划合并，最多 50 个筛选条件。 |
| 118 | 图表点击产生 `interactionFilters`，服务端重新查询所有组件，不在浏览器篡改聚合结果。 |
| 119 | 图表规范只能声明 `DETAIL` 下钻；前端明细使用当前权限查询已返回的行，不执行任意 URL、SQL 或脚本。 |
| 120 | 看板草稿可预览；正式查看只读取 `currentVersionId` 指向的不可变发布版本。 |
| 121 | 列表和版本按工作空间权限过滤；看板查询逐组件调用统一查询服务，因而不同成员应用各自 RLS/CLS 和权限版本。无管理权成员看不到草稿。 |
| 122 | 前端分别显示加载、空数据、局部错误和超时；服务端以 `WidgetResult` 隔离单图失败并标记是否可重试。 |
| 123 | `DashboardStageAcceptanceTest` 断言图表/看板返回值与统一查询服务的原始指标值完全一致，不做前端二次聚合。 |

## 数据与持久化

- 测试/本地无数据库模式使用 `InMemoryDashboardMapper`。
- 生产数据库模式使用 `JdbcDashboardMapper`，落入既有 `bi_chart`、`bi_chart_version`、`bi_dashboard`、`bi_dashboard_version` 和 `bi_dashboard_widget` 表。
- 图表固定 `datasetVersionId`、指标版本和查询计划；看板版本固定布局、筛选定义和图表版本引用。
- API 继续兼容 `/api/v1` 迁移路径，正式路径为 `/api`。

## 人工验收路径

1. 发布一个数据集版本和至少一个指标版本。
2. 在“图表与看板”中新建 KPI、柱线饼、堆叠或明细表，执行校验并发布。
3. 新建看板，选择已发布图表，拖拽组件后预览并发布。
4. 使用两个权限/数据策略不同的成员账号打开同一正式看板，确认组件集合可见、数据行和敏感列分别按成员策略返回。
5. 设置无数据筛选、制造单图查询错误和超时，确认其他组件仍正常展示。
