## 3. 已修复的阻断与高风险问题

1. **P0 浏览器请求阻断**：`ApiClient` 保存原生 `fetch` 后以对象方法调用，Chromium 中可能出现非法调用上下文并统一显示为网络错误。现改为 `globalThis.fetch.bind(globalThis)`；登录 E2E 验证通过。
2. **P0 组件运行时缺失**：页面实际使用的 DatePicker、Drawer、InputNumber、ButtonGroup、Card、Checkbox、OptionGroup、Radio、Slider 未全部注册。现按实际模板清单补齐，避免浏览器把组件降级为未知元素。
3. **P1 路由切换残留请求**：路由离开时统一取消 API 请求；页面自身继续负责取消 SSE、查询、定时器和图表实例。
4. **P1 大报告渲染**：报告详情从一次性渲染全部行改为每页 50 行。
5. **P1 图表包体积**：高级分析从全量 ECharts 改为 LineChart + 必需组件按需注册，页面块从约 506.96 kB 降至 5.63 kB。

## 4. 权限与安全检查

- 未登录路由由全局守卫转到登录页；401 只允许一次会话刷新重放，失败后清理会话；403 进入 Forbidden 页面。
- 企业/工作空间切换会取消请求并清理看板、AI 游标、数据源选择等业务缓存；服务端仍是最终授权边界。
- 创建数据源 E2E 检查了提交凭据后列表不回显明文密码；编辑页也不会从服务端恢复保存的用户名/密码。
- Vue 页面未使用 `v-html`、`eval` 或 `new Function`；AI ChartSpec 仅映射到前端白名单图表，不执行模型脚本或 HTML。
- 下载、支付、同步、导入和 AI 均以服务端任务终态为准；浏览器跳转或 POST 已接受不显示为成功。
- 旧的非路由原生页面类仍包含受控 `innerHTML`，动态值使用 `textContent` 转义；应在后续清理旧实现时删除，当前不构成活动 Vue 路由阻断。

## 5. 性能检查

- 所有页面路由均为动态导入，首屏不会同步加载业务页面。
- ECharts 渲染器单独形成异步块；页面卸载会执行 `dispose`。
- 最终主要产物：主框架 519.82 kB（gzip 164.57 kB）、Canvas 图表渲染器 483.55 kB（gzip 161.10 kB）、全局 CSS 449.19 kB（gzip 63.54 kB）。
- Vite 仅对主框架块给出超过 500 kB 的非阻断警告。后续可引入 Element Plus 自动按需导入进一步拆分，但当前 gzip 体积和路由拆包满足本阶段发布条件。
