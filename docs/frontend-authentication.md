# 前端登录与身份认证

更新日期：2026-10-12

## 登录流程

1. `/api/auth/login` 校验邮箱和密码，签发全局访问令牌及一次性轮换刷新令牌。
2. `/api/users/me/memberships` 查询当前用户的有效企业成员关系。
3. 用户指定企业，或前端选择最近使用/首个可用企业。
4. `/api/auth/switch-tenant` 由全局令牌换取带租户、成员及权限版本的上下文令牌。
5. `/api/tenants/{tenantId}/workspaces` 装载当前企业的活动工作空间，然后进入工作台。

登录任一步骤失败都会清理未完成会话。表单提交期间按钮被禁用，避免重复创建会话。

## 令牌与错误处理

- 普通业务请求只使用租户上下文令牌；成员关系、切换企业和退出使用全局访问令牌。
- 业务请求返回 401 时，全局 API Client 将并发请求合并到同一次刷新；刷新成功后重新签发租户上下文并仅重放原请求一次。
- 刷新失败会清理访问令牌、刷新令牌、租户令牌、用户、成员和工作空间状态，并跳转 `/login?reason=expired`。
- 业务请求返回 403 时进入 `/forbidden`。前端路由和菜单仅用于改善体验，不构成授权；Spring Boot 必须对每个业务接口继续校验租户、成员、权限版本及资源权限。
- `/api/auth/logout` 在服务端撤销会话；前端无论接口是否可达都会完成本地清理。

## 存储边界

当前后端以 JSON 返回刷新令牌，因此前端按现有契约保存在浏览器存储中。页面不得把令牌渲染到 DOM、日志或错误提示。若后端后续支持 `HttpOnly + Secure + SameSite` Cookie，应优先迁移刷新令牌并保留访问令牌仅在内存中，以进一步降低 XSS 窃取风险。

## 验收覆盖

- 前端：登录成功、密码错误、刷新令牌失效、未登录访问受保护路由、401 刷新与请求重放。
- 后端：`AuthApiIntegrationTest` 覆盖登录、错误密码/用户、限流、刷新轮换和退出撤销；`MultiTenantMembershipIntegrationTest` 覆盖多企业成员关系、合法切换及越权企业拒绝。
